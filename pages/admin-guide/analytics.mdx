# Usage analytics

Site administrators can open **Analytics** from the admin dashboard. The dashboard's three traffic graphs always cover the current site; global administrators can select **All sites** on the analytics page. Reporting supports the last 7, 30, 90 or 365 days, including today, in UTC.

Page views count browser page loads and client navigation on the public site, including repeat views. Admin and account pages are excluded. Query changes count as navigation; hash-only changes, re-renders and data refetches do not. JavaScript must run and the collection request must succeed, so these figures are usage indicators, not audited traffic or bot-filtered totals. Each view belongs either to the project in its route or to “Outside projects”. **Weekly signed-in visits are page views, not distinct users or sessions.** Weeks start on Monday; boundary weeks contain only the selected dates.

Contributions started counts the first saved user revision. Contributions completed counts its first submission or acceptance. Reviews completed counts its first acceptance or rejection, including automatic approvals. Saving again, retrying, or resubmitting the same contribution does not increment these milestones again. Canonical edits, template clones, and model imports are excluded. Project attribution uses the capture model's originating project template. A claimed task without a saved revision is not a started contribution, and a review covering several contributions can produce several review outcomes.

Only daily site/project counters are retained in Postgres. Analytics does not store user IDs, hashes, IP addresses, URLs, referrers, user agents, session records, or raw events, and adds no cookies or browser storage. The existing login is used only to choose the signed-in/anonymous counter. Three deduplication flags are kept on the existing revision record; no revision IDs are copied to the analytics tables. Counters remain when contributions or projects are deleted; deleting a site deletes its counters. Existing history is not backfilled. The page shows when collection began.

The reporting API (`GET /api/madoc/analytics`) requires `site.admin`; all-sites reporting also verifies the user's global administrator role. The browser collection endpoint is write-only, validates the site/project and derives login status on the server. It accepts no visitor identifiers or URLs.

This feature minimises analytics data, but it does not change Madoc's existing account, contribution, proxy, or application-log retention. Operators still need to assess their deployment and privacy notice, including whether small aggregate groups can reveal information about an individual. Aggregation alone is not a blanket GDPR compliance guarantee; see the [ICO's anonymisation guidance](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-sharing/anonymisation/how-do-we-ensure-anonymisation-is-effective/).
